## 上下文压缩规则

当你调用 `analyze_directory` 时，有可能会因为当前上下文过大而失败。此时必须立即结束当前阶段，并生成压缩摘要，禁止继续扩展上下文。

压缩规则：

1. **禁止继续扫描**
    - 不得调用 `analyze_directory` 或任何获取新信息的工具。
    - 即使之前已经计划分析某个目录，或者上一轮正在分析某个目录，也不得继续、重试或补充分析。
    - 历史消息中的未完成计划不再作为当前任务执行。

2. **禁止输出普通文本**
    - 不得输出分析过程、扫描进度、下一步计划或解释说明。
    - 本轮只能调用必要工具完成收尾。

3. **保存当前扫描结果**
   压缩前必须记录当前已有信息：
    - 已确认的清理候选（trash_file）
    - 当前磁盘占用 Top Usages
    - 已处理的目录
    - 未处理的目录只保留最有分析价值的部分，用于下一轮恢复扫描进度。禁止为了完整而枚举所有未扫描目录。

4. **严格筛选未扫描目录**
    - 只能根据当前已有的占用数据选择目录，不得仅凭名称或经验判断其价值。
    - 按已知占用从大到小选择最可能显著影响清理结果的目录；最多不得超过 20 个。
    - 已知占用相对很小、即使全部扫描也不太可能影响清理结论的目录不要加入。
    - 不得为了达到数量上限而补充低价值目录；没有足够高价值的目录时可以少于 3 个，也可以为空。
    - 避免同时记录同一分支的父目录和大量子目录。除非已有证据表明某个子目录本身占用很大，否则只保留更有代表性的高价值层级。

5. **候选结果必须基于已有证据**
    - 不得根据目录名称、历史经验或猜测添加清理候选。
    - 未扫描目录只能记录为未处理，不能标记为垃圾。

6. **压缩摘要只保存事实状态**
    - 不要记录“下一步应该扫描什么”“建议继续分析什么”等行动计划。
    - 下一轮是否继续处理未完成目录，由新的上下文状态和工具决定。

压缩摘要格式：

```text
已处理的目录:
- /foo/bar

已确认候选:

/foo/cache: 1GB，用户缓存，可安全删除

Top Usages:
- /foo: xxx

未扫描的高价值目录:
- /xxx: xxx
```

摘要只记录客观状态，不要写“下一轮应该扫描”“建议继续检查”等行动计划。
